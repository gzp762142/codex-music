Aether · 定位手段评估

你的偏移
到底结不结实

「特征码」和「偏移」不是一回事，失效的原因也完全不同。 这一页先分清三类定位手段的稳定性天梯，再给出能直接打分用的评判标准， 最后落到 Aether 现在手里到底是哪一类。

第 0 节 · 先看现状你手里现在是什么

翻了 Offsets.swift，实际情况是这样：

// Offsets.swift — 当前默认值 moduleBase = 0x1047D0000 // dump 时的模块基址 gObjects = 0x111251B00 // 静态 vmaddr 域地址 gNames = 0x111FBA198 gWorld = 0x11148B608 // MemoryProbe.swift — 结构体内部偏移（硬编码在读取链里） UWorld.PersistentLevel = 0xB8 ULevel.Actors = 0xA0 UWorld.OwningGameInstance= 0xB20 APlayerController.Pawn = 0x660 // 特征码： 一个都没有。

这张单子说明两件事：你的结构体偏移没有问题（这类东西天生比较稳）， 但三个全局地址是最脆弱的那一类——而且没有任何兜底手段。 另外 offsets.txt 现在还不存在，所以跑的是源码里的默认值。

第 1 节 · 分类三类定位手段的稳定性天梯

这三样东西经常被混着叫"偏移"，但它们的失效原因完全不同。 分清楚了，才知道该往哪儿使劲。

3

绝对地址 / 静态域地址

比如 gWorld = 0x11148B608。它本质是「模块起始 + 一个固定偏移」， 直接写死在代码里。

为什么最脆：这个数字取决于链接时每个段的排列顺序和大小。 游戏更新时只要任何一个段变大变小、编译器换个版本、静态初始化顺序动一下， 后面所有地址整体移位，三个全废。

版本绑定
2

特征码（Pattern Scan）

在代码段里搜一段字节序列，命中处就是你要找的函数或变量。 比如找「谁在读 GWorld」，就搜那条 adrp + ldr 指令对。

为什么中等：它是从语义上定位——只要那段代码还在做同样的事， 地址怎么变都能找到。但它依赖编译器的输出， 编译器换版本、优化等级变化、函数被内联，特征码就可能失配。

代码绑定
1

结构体内部偏移

比如 UWorld.PersistentLevel = 0xB8。这是从基类指针往后数的字节数。

为什么最稳：UE 的结构体布局是引擎层面的东西， 游戏更新时改动很慢。而且小的偏移（像 0xB8）通常落在结构体头部， 那块区域被改动的概率更低。 代价是：它需要一个可靠的起点——起点断了，它再稳也没用。

布局绑定

这张梯子说明一个反直觉的结论：你缺的不是"更好的偏移"，是"更可靠的起点"。 结构体偏移已经是最稳的那一类了，问题全在它前面那三个全局地址上。

第 2 节 · 评分卡 A特征码好不好，看这六项

给你以后写特征码时自查用。每一项都能当场判断，不需要跑工具。

特征码质量评分 · 六项
A1
唯一性

在整块代码段里，这个字节序列只能命中一次。命中两次以上就完全没用——你没法知道该信哪一个。

合格：全段扫描命中数 = 1　　不合格：命中 2 次以上，或你自己说不清命中了几次
A2
长度

太短会误伤，太长等于把周围的代码也一起绑上——周围代码改动的概率比核心代码高得多。

合格：约 12～24 字节（3～6 条指令）　　不合格：少于 8 字节，或超过 40 字节
A3
通配符比例

adrp 这类指令的立即数会随地址变化，必须打通配符。 但通配符一多，特征码就退化成"模糊匹配"，唯一性会崩。

合格：通配符占比 < 30%，且都集中在地址类指令上　　不合格：通配符成片出现，或用来"猜"不确定的字节
A4
是否跨函数边界

跨两个函数的特征码，等于同时依赖两个函数的相对位置—— 而这恰恰是编译器最容易调整的东西（函数重排、内联、冷热分离）。

合格：完整落在一个函数体内　　不合格：跨越 ret、跨越函数对齐填充
A5
是否依赖编译器脾气

内联、向量化、指令调度、常量折叠——这些优化一开一关，字节序列就变了。 依赖具体寄存器编号或指令顺序的特征码尤其脆。

合格：锚在跨函数的调用约定、字符串引用、常量比较上　　不合格：锚在寄存器分配细节上
A6
锚点质量

不同锚点天生不等价。这是从稳到脆的顺序：

字符串引用 > 跨模块调用 > 独特常量比较 > 指令序列 > 纯字节填充

最常见的错法

拿一段看着很独特的指令直接当特征码，从没验证过唯一性。 这种特征码在编写它的那个版本上跑得通，换个版本就静默失配—— 而且因为你不检查命中数，它可能命中到了别的地方，读回来一堆垃圾，你还以为是偏移错了。

第 3 节 · 评分卡 B偏移链好不好，看这五项

这里说的"偏移"指的是——从起点出发、经过若干级指针跳转、到达目标字段的整条路径。

偏移链质量评分 · 五项
B1
链长

每多一级指针，就多一个失效点。五级链的存活率约为三级链的一半——不是说每一级的失效率特别高，而是它们会连乘。

合格：≤ 4 级　　警惕：5～6 级　　不合格：7 级以上，几乎必然有更短的等价路径
B2
位移量大小

小偏移通常落在结构体头部——那里是基类、虚表指针、常用成员， 布局多年不变。大偏移往往意味着"翻过半个结构体去够一个成员"， 中间被插入字段的概率高得多。

稳：< 0x100　　一般：0x100 ～ 0x400　　脆：> 0x1000（尤其 0xB20、0x660 这类跨结构体的大跳跃）
B3
每一级的有效性校验

这是整份清单里最实用、也最常被跳过的一项。 链断掉的时候，你读到的不是崩溃，而是"一个看似正常的野值"—— 然后这个野值被当成坐标喂进后续计算，屏幕上画出一个荒唐的东西，你还得回头查半天。

每一级指针解引用前检查：
1 非 0　　2 8 字节对齐　　3 落在合法地址区间（模块内或已知堆区）
缺任意一条，链路失效就会伪装成"读到了错误的数据"而不是"读失败了"
B4
是否有替代路径

同一个目标，如果存在两条互相独立的到达路径，你就能拿它们互相对照。 一条断了，另一条还在；两条结果不一致，说明中间有一级不可信。

好：≥ 2 条独立路径，且能交叉验证　　差：只有一条，断了就全瞎
B5
失效时可检测性

链断了以后，你怎么知道？——这是设计时就要想的问题，不是出事后才补。

合格的标准：能说出是哪一级先不成立的，而不是笼统报"读取失败"
不合格：只报一个总结果，无法定位断点

第 4 节 · 三个检验法不写代码也能做的实测

下面三个方法都是"跑一次就有结论"的类型，不需要额外工具。

检验一 · 交叉验证

你现在有 stepWorld 和 stepObjects 两条独立的遍历路径。 让它们都去取同一个目标（比如 UWorld 指针），对比结果。

两条路径算出来的值一致 → 这一级的可信度高。 不一致 → 至少有一条中间环节不可信，先别往下走。

这是唯一一个不需要外部信息就能判断可信度的方法，成本几乎为零。

检验二 · 值合理性

读到的每一个指针，都应该能过一遍常识检查：

指针非 0　　指针 8 字节对齐　　地址 > 0x100000000（不是小数巧合）
落在模块区间内，或落在已知的堆/栈区间

四项全过，才继续往下跳。任何一项不过，立刻停下并记录是哪一级。

检验三 · 时间稳定性

让读取循环连续跑 5 分钟，把每一级的地址记下来。

好的表现：链路中间几级是稳定不变的（对象没被回收就不该动）， 只有叶子节点（坐标、血量）在变。

坏的表现：中间级的指针一直在跳。这说明你读的地址本身是错的， 只是每次都恰好是个能读的野值——这种情况最阴，因为不崩。

第 5 节 · 改造顺序按这个优先级动

P0
先给链路每一级加校验

这件事不需要任何新信息，纯代码改动，而且立刻见效： 从"读到一个野值"变成"明确告诉你第三级断了"。 在加特征码之前，这是性价比最高的一步。

P1
给三个全局地址做特征码

这才是真正解决"版本换代就得重来"的办法。做法是：反汇编游戏， 找到引用这三个全局变量的代码点，提取那段指令做特征码， 运行时拿命中地址反算出变量地址。

顺序上建议先做 GWorld——它的引用点最集中（世界 Tick 里到处在用）， 最容易找到高唯一性的片段。

P2
特征码加"命中数"自检

搜完必须报告命中了几次。命中 0 次是失配，命中 2 次以上是特征码不合格， 只有恰好 1 次才算可用。没有这个检查，上面 P1 做的功可能白做。

P3
保留绝对地址作为备用路径

别急着把写死的地址删掉。让它和特征码并存： 两者结果一致 → 高可信；不一致 → 说明版本变了，特征码该重新提取。 这本身就是一条免费的交叉验证。

第 6 节 · 一张速查表看到数字时该问什么

看到什么 说明
0x11148B608 这样的长地址 静态域地址。跨版本不可移植，每次更新都要重新 dump。
0xB8、0xA0 这样的小偏移 结构体头部成员。这是好偏移，不用担心它。
0xB20、0x660 这样的大偏移 跨了半个结构体。能用，但要知道它的失效概率比小偏移高。
一段指令字节 特征码。必须问：命中几次？通配符占多少？跨没跨函数？
读到一个非零但明显不对的值 典型的"链断在中间"。不是崩溃，是野值。查 B3 那一项。
中间级指针每帧都在变 地址本身错了。正常对象在生命周期内地址不该动。

四句话收尾

  1. 你的结构体偏移是好的那一类，别去动它。真正脆的是 gObjects / gNames / gWorld 这三个静态域地址——它们决定了整条链的起点。
  2. 没有特征码，就没有跨版本能力。现在每次游戏更新都得重新 dump 一遍全量偏移，这是最大的时间成本，也是加特征码能省下的东西。
  3. 加校验的收益比加特征码来得更快。校验不需要新信息、当天就能做完，而它会把"读到一个荒唐的值"变成"第三级断了"——排查时间从几小时变成几秒。
  4. 两条独立路径互相对照，是免费的可信度检测。你已经有 stepWorld 和 stepObjects 了，让它们互证，比任何单向检查都可靠。
