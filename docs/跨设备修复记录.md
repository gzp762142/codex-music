# 跨设备修复记录（面向客户分发）

背景：项目此前只在作者自己的 iPad Pro M2 / iPadOS 16.4.1 上验证过。
要给客户分发，必须检查其余设备/版本会怎样。以下为审查后落地的改动。

---

## 一、本轮改动（3 个文件）

### 1. `kfd/libkfd/info/dynamic_info.h` —— 全表 `perf_supported` 置 false

**问题**：`22.5.0` 与 `22.6.0` 两条填了 8 项 `kernelcache__*` 静态地址并把
`perf_supported` 置 `true`，但那些地址只对注释里声明的**那一个机型**保证：

```
// iOS 16.5 - iPhone 14 Pro Max          → T8120 的 kernelcache
// iOS 16.6 - iPhone 12 Pro              → T8101 的 kernelcache
```

而版本匹配只看 Darwin 前缀（29 字节，止于 `'22.5.0:'`），于是**该版本下所有设备**
都会套用这一份偏移。`perf_run()` 拿它算 kernel slide / kernel base，
一旦不符就在 `perf.h:114` 的 `kread` 上打在错误或未映射的内核地址 —— 与 22.4.0
那次同型的失败。

**改动**：全表 `perf_supported = false`，`kernelcache__*` 一律留 0。
kernel base 改由 `km_scan_kernel_base()` 扫描获得（本来就有这条路径）。

**理由**：perf 只是把 kread 从"半随机游走"升级成高效物理读写，**不是功能必需**；
而面向多机型的发布版，偏移不确定性的代价远大于它的收益。

### 2. `kfd/libkfd/info/dynamic_info.h` —— 删除 macOS 条目

原文件末尾有两条 macOS 条目：注释标 `macOS 13.4 - MacBook Air (M2, 2022)`（`kern_version = "todo"`）
与 `macOS 13.5 - MacBook Air (M2, 2022)`（`Darwin 22.6.0 ... T8112`）。

**关键澄清**：这两条**不是**"iOS 16.6 的重复条目"。macOS 13.5 的 Darwin 内核版本
**恰好也是 22.6.0**，所以它与 iOS 16.6 那条共用 Darwin 号。在 iOS 上它们永远不会命中，
但留在 iOS-only 工程里只会造成误读（审查中就一度被误判为「iOS 条目互相抢占」）。
已全部删除。

### 3. `KernelMemory.m` —— 新增系统版本门

**问题**：部署目标是 **iOS 13.0**（`project.yml` / `MusicIdentity.xcconfig` /
`Info.plist` 的 `MinimumOSVersion` 三处一致），所以 **iOS 13/14 设备装得上**。
但 kfd 的三个 PUAFF 都要 iOS 15.0 起才存在，且 `dynamic_info.h` 最早只到 Darwin 21。

结果：那些设备会在 `info_init()` 里撞 `assert_false("unsupported osversion")` → app 闪退，
而不是收到一句能看懂的话。

**改动**：新增 `km_version_is_supported()`（`KernelMemory.m` 定义在 `km_version_is_listed`
之后），在调用 `kopen` **之前**拦截：

```c
if (!km_version_is_supported()) {
    NSString *ver = [[NSProcessInfo processInfo] operatingSystemVersionString];
    if (err) {
        *err = "iOS 版本不在 kfd 支持区间（15.0 – 16.6.1）："
               "低于 15.0 没有可用的 PUAFF，高于 16.6.1 三个 PUAFF 均已修复";
    }
    NSLog(@"[KernelMemory] unsupported OS, refusing to run exploit: %@", ver);
    return false;
}
```

**两道门的分工**（互补，不重复）：

| 检查 | 位置 | 负责 |
|---|---|---|
| `km_version_is_listed` | 已有（`km_init` 中，早于版本门） | **上界**：表里有没有这个 Darwin 版本（> 16.6.1 → 无条目 → 拦） |
| `km_version_is_supported` | 新增（`kopen` 之前） | **下界**：Darwin 主版本 ≥ 21（iOS 13/14 → Darwin 19/20 → 拦） |

iOS 15（Darwin 21）在表里**有**条目（`Darwin Kernel Version 21.0.0`），
所以两道门叠加后它**仍会放行** —— 这是正确行为。

## 二、仍在处理的问题

### A. `T1SZ_BOOT` 编译期硬编码（待方案）

```c
// info/static_info.h:22
#define T1SZ_BOOT    17ull
// :97-100
#define PTR_MASK      ONES(64-T1SZ_BOOT)     // = ONES(47)
#define PAC_MASK      (~PTR_MASK)
#define UNSIGN_PTR(p) (SIGN(p) ? ((p) | PAC_MASK) : ((p) & ~PAC_MASK))
```

`17` 只对 **iPhone 14 系 / A16 / M 系**正确，**A15 及更早需要 25**。
而它影响 `info.h` 的 `current_map` / `current_pmap` / `kernel_map` / `kernel_pmap`、
`perf.h` 的 `fileproc` / `fp_glob` / `cdevsw`、以及 `kwrite_dup.h:43` 的判据。

错 → 内核 VA 高位被错误清除 → `kernel_map` / `kernel_pmap` 变垃圾 → 后续全错，
**且没有任何检查会拦住它**（自检的 `p_pid` 比对不走 `UNSIGN_PTR`）。

**这不是一个错值，是结构性问题**：单一二进制无法同时满足 17 与 25 两类设备。
已派独立评估（改造方案对比 / 改动面 / 风险）。

### B. iOS 15 条目 `ios__*` 全为 0 —— 已改为「明确拒绝」

```
[#1] Darwin 21.0.0  →  ios__IndexedTimestampPtr = 0,
                       ios__AllocSize = 0,
                       ios__PixelFormat = 0,
                       ios__UseCountPtr = 0,
                       ios__ReadDisplacement = 0,
```

iOS < 16 会被分派到 **IOSurface 后端**（`@available(iOS 16.0, *)` 不满足），
而该后端**完全依赖**这五个偏移。代码注释自己也写着「IOSurface 那条路只在
iOS 15 成立」—— 而这条路的偏移根本没填。

**处理**：版本门把门槛从 Darwin 21 抬到 Darwin 22：

```c
if (major < 21)  { *why = "系统版本过低：…（需要 iOS 16.0 及以上）"; return NO; }
if (major == 21) { *why = "iOS 15.x 暂不支持：…该后端的偏移尚未取到实测数据"; return NO; }
```

理由：补齐 iOS 15 偏移**需要真机实测数据**，而作者手上没有 iOS 15 设备。
与其让客户在 iOS 15 上撞莫名其妙的失败，不如给一句明确的话。
（若日后拿到 iOS 15 实测偏移，把 `major == 21` 那段去掉即可。）

## 二之二、独立复核发现并已修复的两处

### C. 两条短 key 永不命中（真实缺陷，已修）

`info.h:102` 的 `kfd_version_prefix_length = 29`（= `strlen("Darwin Kernel Version 22.5.0:")`），
而表里两条 key 原本只有 **28** 字符：

```
"Darwin Kernel Version 21.0.0"    // 28 —— 少一个 ':'
"Darwin Kernel Version 22.0.0"    // 28 —— 少一个 ':'
```

`strncmp(..., 29)` 比到第 29 位时，真 banner 是 `':'`、key 是 `'\0'` → **永不匹配**。
于是这两条「兜底条目」（表头注释声称 *"22.0.0 answers for every Darwin 22 banner"*）
**完全失效**，实际只覆盖 22.4.0 / 22.5.0 / 22.6.0 三个精确版本。

**已修**：给两条 key 补上结尾 `':'`，现在长度都是 29，与 `prefixLength` 对齐。
修完后 `Darwin 22.0.0:` 能正常接住 iOS 16.0–16.3.1。

> 这个缺陷是静态可证的：`"Darwin Kernel Version 22.0.0"` 长度 28，`+":"` = 29 = `prefixLength`。

### D. 我上轮注释里的误导（已修）

我上轮把 `dynamic_info.h` 里「22.6.0 must be changed to 25 instead of 17」改成
「另见 t1sz 的按设备取值问题」——但**全工程 `T1SZ_BOOT` 只有 `static_info.h:22`
一处硬编码，不存在"按设备取值"机制**。我的指引落空，还抹掉了原版那条可操作信息。
（T1SZ_BOOT 的真实处理见上方 A 节，待独立评估结果。）
