## 一、为什么做这一件事（它解锁三处）

本工程的读原语（libkfd `kread_sem_open`）是**让内核替我们解引用**目标地址：
把一个本进程持有的内核对象的指针字段改写成目标地址，再由内核从那里逐字段读回。
因此**踩到未映射地址 = 内核态 same-EL data abort = 整机重启**，没有 fault-recovery，
**也没有"读到垃圾"这个中间态**。

这导致三处功能被迫停用，原因**同一个**：

| 停用处 | 位置 | 停用理由 |
|---|---|---|
| `proc → proc_ro → task` 链 | 新增需求 | 第二步要"把第一步读出的值当地址读" |
| `p_list` 遍历按 pid 定位 proc | `KernelMemory.m:2299` `KM_ENABLE_PLIST_WALK 0` | 链上指针可能落在内核空洞 |
| kernel base 反向盲扫 | `KernelMemory.m:670` 已整段删除 | 唯一一处"未验证地址上连续盲扫" |

代码里把出路也写明了（`KernelMemory.m:2285-2287`）：

> 恢复前提：拿到「**能证明某个地址确实已映射**」的手段 —— `ptov_table` 的等价物，
> 或**逐级页表验证下钻**。

**本任务实现后者。** 关键区别（这是整个方案成立的理由）：

> **盲扫会去读目标地址；页表验证只读"已经确认映射的页表页"，输出是一个判定，不是一次读取。**
> 所以它**不构成盲读**。

## 二、根信任：一条前提，必须显式标注

从 `kernel_pmap` 读出顶层表地址（`pmap + KM_PMAP_TTE_OFFSET`）这**一次读**，
无法用本方案自己来证明其安全（那会递归）。它的依据是**链路**：

```
kernel_proc  ─(已确认正确)→  kernel_task = kernel_proc + dynamic_info(proc__object_size)
kernel_task  ──dynamic_kget(task__map)──→  kernel_map
kernel_map   ──static_kget(struct _vm_map, pmap)──→  kernel_pmap
```

全程是「**已确认对象 + 已知偏移**」，无一处猜测（见 `libkfd/info.h:155-176`）。
且现有代码**已经**在这么做：`km_page_table_walk` 的 `KernelMemory.m:1656`
就是 `km_read64(pmap + KM_PMAP_TTE_OFFSET)`。

**要求**：代码里把这一步标成 `// ROOT ASSUMPTION: <理由>`，并在诊断里单列一行说明
"从第二级起才有验证"。**不要把它写成"已证明安全"。**

## 三、要实现的接口

```c
/// 只读：判定内核虚拟地址 va 是否【已映射】。
/// 不读 va 本身，只读页表；输出是判定，不是数据。
/// 返回 true = 已映射（可以安全地送进 kread）。
/// 返回 false = 未映射 / 无法判定 —— 两者调用方都必须**停下**，不许换地址重试。
bool km_va_mapped(uint64_t va);
```

**硬要求**

1. **绝不读 `va` 自身**。全函数只允许读：`pmap` 对象、各级页表项、块/页描述符本身。
2. **不依赖 `g_linear_map_valid` / `g_linear_delta`**。那套机制目前是死锁态
   （`KernelMemory.m:2179-2190` 记录了闭环），而本函数不需要 delta ——
   它不下钻"表项里的 PA 补回 KVA"，只判有效位。
3. **失败即停**：任一级读出失败或表项无效 ⇒ 立即返回 false，**不换偏移、不重试**。
4. **每级只能前进一次**，不许有循环里的"再试"。本机是 **T1SZ_BOOT = 17 对应的
   三级结构：L1 / L2 / L3**（工程里就是 `shifts[3]` / `masks[3]` 三个元素，
   没有 L0）——**不要按 ARM64 四级教科书写法补一层 L0**，否则索引会整体错位。
   下钻上界固定为 3 级。
5. 只读模块，**不许有写操作**。

## 四、页表几何（本工程已定义，直接用 —— 值已核实）

16 KB 页。工程内已有常量（`KernelMemory.m`，**下列值已核对过，不是本文推测**）：

```
KM_PMAP_TTE_OFFSET = 0x00        (:208)
KM_L1_SHIFT = 36ULL              (:1505)
KM_L2_SHIFT = 25ULL              (:1506)
KM_L3_SHIFT = 14ULL              (:1507)
KM_L1_MASK  = 0x00007ff000000000ULL   /* 11 bits at 36 */   (:1516)
KM_L2_MASK  = 0x0000000ffe000000ULL   /* 11 bits at 25 */   (:1517)
KM_L3_MASK  = 0x0000000001ffc000ULL   /* 11 bits at 14 */   (:1518)
```

三级各 11 位索引，与 16 KB 页一致（`2^11 × 16 KB = 32 MB` 是 L2 块的覆盖粒度）。
`L1_SHIFT = 36` 说明这是 **T1SZ_BOOT = 17 的三级结构**，不是四级。

**请先读这些常量的定义并确认，再把下钻逻辑建立在其上**；
若发现某个常量与上表不符或与 ARM64 16 KB 页布局矛盾，**先报告，不要自行改**。

已有的 `km_page_table_walk`（`KernelMemory.m:1622`）是**同一条页表链**的实现，
它的下钻部分**可以直接参照**。其中两条注释是踩过的坑，务必读：

- **"L1 / L2 允许块描述符直接落地；L3 只认页描述符"**；
- **循环上界必须是 `level <= 2` 而不是 `< 3`** —— 一旦 L3 表项的 bit1 为 1
  （表描述符形态），旧写法会继续下一轮、读到 `masks[3]` / `shifts[3]`
  （越界读栈内存），再拿垃圾索引去读。

## 五、判定规则（请你核实并补全，不要照抄本文）

- 每一级：先用该级 `MASK` / `SHIFT` 从 `va` 取索引，读表项；
- 表项 **valid 位（bit 0）为 0** ⇒ **未映射，立即返回 false**；
- 若该级表项是**表描述符**（bit 1 = 1）⇒ 取下一级表地址，继续下钻；
- 若该级表项是**块描述符**（bit 1 = 0）⇒ 映射在块粒度成立，
  **L1/L2 到此即可返回 true**（16 KB 页下 L2 块覆盖 32 MB）；
- 走到 L3 且是页描述符 ⇒ 返回 true。

**请核实上面每一条**（尤其 valid 位与描述符类型的位定义、
以及 16 KB 页下各级的覆盖粒度），并在代码注释里写上依据（ARM64 ARM 手册的章节名或
工程内已有的等价实现）。
